# Задача 18. Реализация планировщика команд

Цель: реализация длительных операций с использованием планировщика и стратегии Round Robin.

## 1. Реализованные компоненты

    IScheduler - интерфейс планировщика с методами HasCommand(), Select(), Add().
    Scheduler - реализация с циклической стратегией Round Robin.
    ServerThread - команды из очереди перекладываются в планировщик, выполнение через Select().
    LongCommand - длительная команда, выполняемая за несколько вызовов Execute().
    
## 2. Оптимизация ожидания и синхронизация потока

Для извлечения элементов из очереди используется неблокирующий метод TryTake(). Это позволяет рабочему потоку непрерывно обрабатывать задачи из планировщика, не останавливаясь на пустой входной очереди. Если команды отсутствуют как во входной очереди, так и внутри самого планировщика, поток переводится в режим ожидания с помощью механизма AutoResetEvent.

## 3. Эффективность планировщика

Замеры проводились 1000 раз для каждого варианта, чтобы получить средний результат.
Каждая команда выполняет 50 шагов.

    Команд: 1, Среднее время: 0.27 миллисекунд, Эффективность: 100.0%
    Команд: 5, Среднее время: 0.37 миллисекунд, Эффективность: 368.7%
    Команд: 10, Среднее время: 0.33 миллисекунд, Эффективность: 820.3%
    Команд: 20, Среднее время: 0.48 миллисекунд, Эффективность: 1134.1%
    Команд: 50, Среднее время: 0.87 миллисекунд, Эффективность: 1562.3%
    Команд: 100, Среднее время: 1.43 миллисекунд, Эффективность: 1893.7%

Это показывает, что планировщик эффективно распределяет время между командами, и увеличение их количества не приводит к значительному росту времени выполнения.
