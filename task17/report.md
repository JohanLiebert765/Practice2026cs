# Задача 19. Реализация длительных операций

Цель: предоставить возможность выполнения команд, для полного завершения которых требуется более одного вызова Execute.

## 1. Реализованные компоненты

    ICommand - добавлено свойство IsComplete для индикации завершения команды.
    Scheduler - реализован Round Robin: команды остаются в планировщике, index двигается по кругу, удаление при IsComplete.
    CountingCommand - длительная команда с id и счётчиком вызовов, завершается после заданного количества шагов.

## 2. Механизм длительных операций

Команда остаётся в планировщике до завершения. При каждом вызове Select() индекс сдвигается на следующую команду, обеспечивая циклическое чередование. После выполнения Execute() проверяется IsComplete, в случае если команда завершена, она удаляется из планировщика.

## 3. Иллюстрация работы

5 экземпляров CountingCommand выполняются по 3 вызова каждый. Round Robin обеспечивает чередование:

    Поток 1 вызов 1
    Поток 2 вызов 1
    Поток 3 вызов 1
    Поток 4 вызов 1
    Поток 5 вызов 1
    Поток 1 вызов 2
    Поток 2 вызов 2
    ...
    Поток 5 вызов 3

После завершения всех команд поток останавливается через HardStop.

## 4. Зависимость времени от длительности команд

Замеры проводились 100 раз для каждого варианта. 5 команд с разным количеством шагов.

    Шагов на команду: 1, Среднее время: 0.42 миллисекунд
    Шагов на команду: 5, Среднее время: 0.52 миллисекунд
    Шагов на команду: 10, Среднее время: 0.61 миллисекунд
    Шагов на команду: 20, Среднее время: 0.78 миллисекунд
    Шагов на команду: 50, Среднее время: 1.14 миллисекунд
    Шагов на команду: 100, Среднее время: 2.18 миллисекунд
    Шагов на команду: 200, Среднее время: 2.47 миллисекунд
    Шагов на команду: 500, Среднее время: 5.95 миллисекунд

Зависимость линейная - время растёт пропорционально количеству шагов. Это показывает, что планировщик не вносит дополнительных накладных расходов при увеличении длительности команд.
